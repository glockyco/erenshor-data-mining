# Script changes for Verses of Adventure

## Scope and reading convention

This change record compares build 24405256 with playtest build 26769622. Old source means `variants/main/backups/build-24405256/scripts/Assembly-CSharp/`. New source means `variants/playtest/unity/ExportedProject/Assets/Scripts/Assembly-CSharp/`. Script references below are relative to the new source tree and line numbers refer to that snapshot.

The review input is every `diff -u` named by `/tmp/scriptdiff.txt`, all new top-level files, and the new `Synty` subtree. The inventory contains 267 changed files, 31 new top-level files, and that new directory. Explicit zero, false and null initializers, local-variable renaming, equivalent loop rewrites and decompiler control-flow reshaping are not treated as mechanic changes. The triage tables account for these files as well as presentation-only changes.

Registry references were checked against `src/tools/CodeFacts/specs/erenshor-facts.json`, `behaviour-coverage.json`, and `code-fact:` consumers in `src/erenshor`. A listed fact identifies an existing contract that this change touches. It does not mean the fact already accepts the playtest rule. "Outside registry" means there is no existing fact for the particular changed rule, even when other behavior in the same method is covered.

These are static shipped-source observations. No build, test, export or game run was performed. Current serialized assets were read only to resolve the explicitly requested gate, boss, quest and starter identities. Their old asset versions are not part of this script comparison, so those bindings are not presented as proven asset deltas.

### Charisma and the Mind label

`SpellVessel.CalculateCharismaModifier` at `252-259` has not changed its formula. In both trees the caller supplies `round(5 * CHA * ChaScaleMod / 100)`, then the helper divides that integer by 100 for a player or SimPlayer and returns 0 for an ordinary NPC. The nominal contribution before rounding is therefore `CHA * ChaScaleMod / 2000` in both builds. The old status-effect subtraction `CHA * ChaScaleMod / 200` also survives in the new `CheckStatusEffectResist` at `2387-2390` for player-like casters. These existing rules are outside registry. There is no evidence in this comparison for replacing the ordinary spell charisma formula with the Bard curve.

The new formula is `BardSong.CalcCharismaBonus` at `103-120`. With `c = CHA * ChaScaleMod / 100`, the song multiplier is `1 + 1.5 * clamp01(c / 500)^1.1`, plus `0.1 * ln(1 + (c - 500) / 200)` when `c > 500`. The old build had no Bard song multiplier. `ProcessSong` at `134-248` includes that multiplier in base direct damage and healing, and `UseSkill.CommitBardSong` at `2221,2296,2333,2416` multiplies those bases by it again. A calculator that applies the curve only once would not match this source. This new curve is outside registry.

`CalcStats.MouseOverCha` at `220-233` changes the displayed proficiency name from "Mind" to "Persuasion". `ItemInfoWindow.DisplayItem` at `423` makes the same text replacement. The identifiers remain `Cha`, `ChaScaling`, `ChaScaleMod`, `ChaScaleSpent`, `GetCurrentCha` and the existing class charisma benefit fields. This is a string change, not a serialized-field rename. It is outside registry. Keep database keys stable and update human-facing proficiency labels where they are intentionally mirrored.

`ZoneAnnounce.cs:40` adds `NeverRain`, default false. In `AtmosphereColors.Update:466-511`, both rain-object activation sites require a non-null zone record with `NeverRain == false`. ## Pipeline implications

The substantive new contracts are Bard class and song data, source-owned status scaling and auras, revised combat and status formulas, off-zone Sim leveling, raid-tier and build-sensitive Sim gearing, spoken passage activation and boss-dependent accompanist spawns. The existing registry already names several affected entry points, but most new rules above are outside it.

Update existing fact matchers only after deriving their new behavior. In particular, the chessboard choice list, spell travel destination, direct auction draw cap, Sim generated-gear gates, player class/start paths, weather rendering versus logical rain, and status overloads must not be made to pass by dropping their assertions. Export serialized bindings for the Glowmere wall and Skald spawn dependencies. Keep key-door access, ritual-portal access and direct spell travel as separate routes. Preserve current save identifiers and do not infer newly introduced gameplay from source formatting changes or unchanged generic controllers.
